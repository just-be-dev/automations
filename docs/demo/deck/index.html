Let’s consider an automation task

When someone new joins, welcome them on Slack, send our welcome email, and book 30 minutes with their manager. Three days in, check how it’s going.

Act one: agent delegation

You hand an AI agent the job and check its audit log after it runs.

Act two: agent-built workflow

You read the plan and iterate on it before it runs.

Both acts start from this exact sentence. It's deliberately ordinary, and a little ambiguous: 'welcome them on Slack' could mean a DM, a team channel, or the whole company. Watch where each approach lets you catch that.

You grant trust before the run and check the work after it.

Permissions are broad

They cover kinds of action, so the agent picks the specifics as it runs.

The log is a receipt

It records what one run did. The next run is decided again from scratch.

So in act one, you grant trust before you know what you're trusting, and you verify after the fact. Permissions are categories. The log is a receipt. And every run gets decided again.

How the two approaches compare

Question Agent delegation Agent-built workflow
When do you learn what it will do? After a run, from its output and log Before saving, from the plan on screen
What does a permission cover? A kind of action, like sending email The steps that use an operation, with their exact messages
What does an approver see? One action, in the middle of a run The finished message inside the plan it belongs to
How do you update it? Re-prompt the agent and run it again Ask the planner, then read the changed step
Where do problems show up? In the agent trace or audit log On the step in the run that caused them
Will the next run match this one? The agent decides again each time It follows the same saved plan
Here's the whole argument in one table. The left column isn't wrong; it's just later. Every row on the right moves the moment of understanding to before anything runs.

Agents and workflows aren’t mutually exclusive.

Agents can run workflows

An agent can start a saved workflow and follow its steps.

Workflows can invoke agents

A workflow step can hand a task to an agent.

Confidence for the user

People understand what actions will be performed on their behalf.

Agents and workflows aren't mutually exclusive. Agents can run workflows, and workflows can invoke agents. The goal is to give people confidence that they understand what actions will be performed on their behalf.
